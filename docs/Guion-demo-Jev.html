Cómo se le habla a Jev

Jev (TypeSafe AI) es un modelo System One: no genera texto, responde preguntas tipadas con probabilidades calibradas. Cada llamada es un POST https://api.typesafe.ai/v1/systemone con tres campos: model (jev-1.13.0), state (los datos: un ticket, una función o una PR) y questions. Cobra solo los tokens de entrada: $0.042 por millón.

TipoQué devuelveEjemplo en la demo
choiceUna opción de una lista cerrada, su confianza y la probabilidad de cada opciónPrioridad: critica / alta / media / baja
noulUna probabilidad de 0 a 1 de que algo sea verdad (sí/no)¿Necesita a un humano? ¿Se traga errores?
scoreUn valor en una escala ordenada (0 a N) con su leyendaSeveridad de 0 (limpia) a 3 (cobros incorrectos)

Anatomía de un prompt a Jev

Con un LLM escribes un prompt de texto libre y lees texto libre. Con Jev el "prompt" es estructurado y tiene tres partes:

  • state: los datos sobre los que se decide (un ticket, una función o una PR) como JSON. Solo hechos, nunca instrucciones.
  • instructions: la pregunta, en una frase. Debe decir qué juzgar y, si hace falta, qué no juzgar ("el impacto de negocio, no lo alarmante del texto").
  • criteria: las opciones posibles, cada una con una descripción concreta. Es la parte que más pesa: Jev compara el state contra cada descripción. Las descripciones vagas dan probabilidades repartidas y confianzas bajas; con ejemplos concretos ("cobros duplicados", "un navegador") la confianza sube.

Cómo se lee la respuesta:

  • choice devuelve choice (la opción ganadora), probabilities (una por opción, suman 1) y confidence (qué tan segura está Jev de la ganadora). Cuando dos opciones están parejas la confianza baja aunque una gane: en la demo 3, PR-15 dio alta 37 % frente a media 35 % y confianza 6 %.
  • noul devuelve un solo número de 0 a 1: la probabilidad de que la afirmación sea cierta (0.97 = "casi seguro que sí").
  • score devuelve score, el promedio ponderado de la escala: con probabilidades 2 % / 2 % / 59 % / 37 % para 0, 1, 2 y 3, el score es 2.3.
La regla de oro de la demo: Jev nunca "decide la acción". Devuelve probabilidades; tu código, con umbrales escritos y versionados, decide qué hacer. Si Jev clasifica mal, se afinan las descripciones de los criteria, no los umbrales.

En la sección de cada demo está el texto exacto de cada pregunta y de cada opción. Las opciones se llaman criteria: son lo único que se afina cuando Jev clasifica mal. Los umbrales no se tocan para "hacer que salga".

Qué decide tu código

En shared/thresholds.ts, con la confianza mínima de las tres respuestas (tipo, prioridad, equipo):

si needs_human ≥ 0.50        → escalate         (no aplica nada; etiqueta "escalado")
si confianza mínima ≥ 0.70   → apply            (escribe tipo, prioridad y comentario)
si confianza mínima ≥ 0.50   → apply_and_flag   (escribe y etiqueta "revisar")
si no                        → escalate         (etiqueta "escalado")

Mapeo a Jira (proyecto en español), en jira-triage/jira.ts: bug → Error, feature → Historia, deuda técnica y soporte → Tarea; crítica → Highest, alta → High, media → Medium, baja → Low. El equipo va en el comentario (KAN no tiene un campo "Equipo" de lista).

Archivo: code-health/scan.ts. El state lleva: archivo, nombre de la función, líneas, parámetros, señales baratas (awaits, catch sospechoso, literales…), las funciones parecidas (similar_to) y el código fuente (hasta 6,000 caracteres). Una señal cuenta como marca si su probabilidad es ≥ SCAN_THRESHOLD (0.60).

responsabilidades choiceHow many unrelated responsibilities does this function have? (single responsibility principle) Judge reasons to change, not number of steps.
unaOne job, even with several steps: validating input, calling one service or repository, and mapping or returning the result is ONE responsibility (orchestration). Thin wrappers, delegations to a provider and transactional wrappers also count as one.
variasMixes concerns that change for different reasons in the same body: e.g. computes money AND sends an email AND writes audit logs or metrics AND changes order status, or business rules mixed with formatting of notifications.
traga_errores noul¿Captura un error y lo oculta devolviendo éxito o un valor inventado, en vez de propagarlo o reportarlo?
trueHay un catch que devuelve ok/true, un id falso o un valor por defecto como si nada hubiera pasado
falseLos errores se propagan, se devuelven como error o se registran de forma explícita
muta_entrada noul¿Modifica directamente un objeto o arreglo que recibió como parámetro?
trueAsigna propiedades o hace push sobre un parámetro; quien llamó ve el cambio
falseTrabaja sobre copias o devuelve valores nuevos
numero_magico noul¿Usa números literales con significado de negocio sin nombre (tasas, umbrales, porcentajes)?
trueAparecen literales como 0.16, 1.16, 0.9 que representan impuestos, umbrales o reglas de negocio
falseLos números están nombrados como constantes o son triviales (0, 1, 100 para redondear)
logica_duplicada noulConsiderando las funciones similares listadas en similar_to, ¿duplica lógica que ya existe en otra función, con variaciones sutiles?
trueReimplementa el mismo cálculo o regla de negocio que otra función listada, pero con fórmula, redondeo o condición distinta
falseNo hay función similar, o la similitud es estructural: un método público que delega en su versión privada (create/create_), varios métodos que llaman al mismo proveedor con distinto método, o CRUD con la misma forma
severidad scoreSi un desarrollador toca esta función para la tarea, ¿qué tan probable es que los problemas detectados causen un bug en producción?
0Ninguno: la función está limpia
1Bajo: deuda de estilo, no afecta el comportamiento
2Medio: puede producir resultados incorrectos en casos borde
3Alto: produce cobros, estados o montos incorrectos en casos normales

9. Qué se ajustó en el ensayo (por si preguntan)

  • Jev rechazaba todas las llamadas reales (400): el cliente mandaba un campo user que la API no acepta. Se quitó en shared/jev.ts.
  • El triage escribía en issues equivocados: emparejaba por posición y los 8 en Finalizada descuadraban el orden. Ahora empareja por título (jira-triage/batch.ts).
  • Prioridad: con criterios vagos Jev daba "alta" a casi todo y escalaba 15 tickets; con criterios concretos en inglés escalan exactamente los 3 ambiguos.
  • Pre-vuelo en Medusa: de 21 marcas de ruido a 1–2 marcas útiles afinando las opciones de responsabilidades y duplicación. La referencia para no romperlo es results-backup/code-health-T03-medusa.json (sample-app ya no está en el repo).
  • Claude por CLI: la API de Anthropic no tiene saldo; CLAUDE_ENGINE=cli usa claude -p con tu sesión. Sin herramientas ni MCP, cada llamada entra con ~1,000 tokens, así que los costos siguen limpios.
  • Demo 1 en vivo sin webhook: en lugar de túnel y webhook, el skill /triage crea el issue con el MCP y lo clasifica.
  • Un "antes" para cada demo: las demos 1 y 2 solo medían a Jev. Ahora batch y scan tienen --mode=direct (todo a Sonnet, sobre los mismos datos reales), como ya lo tenía la demo 3. npm run reset los conserva porque se precalculan una vez.
  • Lo que encontró el ensayo completo: ver la sección 10.
